# 馆藏研究结论发布链

项目记录馆藏器物、研究证据、竞争性解释和各类公众说明版本，使展签、课程与出版物使用可追溯的结论。Node.js 代码提供样例读取与基础校验。

执行 `npm test` 检查资料完整性。

## 研究结论与传播校订服务（`src/service.js`）

以事件溯源（`src/store.js`，追加式日志、可按日期重放）实现结论从评审到传播的全链路校订：

- **证据分层**：器物特征、出土背景、检测记录、文献引文分类登记，研究者观点单独保存；同一主张下多条竞争解释并存，互不覆盖。
- **学术流程门控**：`standard` 流程需两名不同评审人批准，`urgent`（紧急勘误）需一名批准且必须附理由；未走完流程的修订不能发布到任何渠道。
- **修订与撤回**：结论在“可能 / 已证实”之间调整或被撤回时，生成带理由的新修订（旧版本不被修改），并通知仍在分发旧版本的渠道；渠道展示日志只追加、不覆盖，旧展签永远可查。
- **译文锁定**：译文绑定具体事实版本，同一版本同一语言只能锁定一次；查询无对应译文时明确缺失，绝不拿旧版本译文冒充当前表述。
- **迟到回执不降级**：合作机构离线确认旧版本的回执只记录为 stale，绝不修改已发布或已展示内容；渠道版本只允许前进，不允许回退。
- **双视角查询**：公众查询得到当前（或某历史时点的）对外表述与证据边界；内部人员可按历史日期还原任一渠道当时的展陈文字、批准者和未采纳意见。

`test/service.test.js` 以种子资料中的陶俑与研究主张演示完整场景：并行评审发布 → 新检测记录触发紧急勘误 → 外借展览延迟同步并收到迟到回执 → 所有渠道缓存收敛到正确版本，且每个渠道曾经展示过的内容完整保留。
